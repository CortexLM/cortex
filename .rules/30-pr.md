# 30 — Pull requests

One PR, one intent. Target **`main`**.

## Hard requirements

1. **Attestation.** `.github/PULL_REQUEST_TEMPLATE.md` contains four
   checkboxes. A PR is not complete — and `pr-gate` CI fails on a
   non-draft PR — until all four are ticked:

   - I read all of `.rules/` before opening this PR and before marking it ready
   - `AGENTS.md`, `README.md` and `.rules/` are accurate for this change, or N/A with a reason below
   - Local pre-prod gates in `.rules/20-pre-prod-local.md` all passed
   - Version bumped per `.rules/50-versioning.md`

   Do not tick a box you did not earn. The point of the gate is that the
   reviewer can trust the four claims without re-deriving them.

2. **Draft until earned.** Open as a draft while you iterate. `pr-gate` reports
   open attestations on a draft without failing, and enforces them the moment
   the PR is marked ready for review. Never mark ready with an unticked box.

3. **Gates green locally.** All of [`20-pre-prod-local.md`](20-pre-prod-local.md),
   not a subset you felt was relevant.

4. **Version bumped.** See [`50-versioning.md`](50-versioning.md). CI fails a PR
   whose version matches `main`.

5. **Docs in the same PR.** `AGENTS.md`, `README.md`, `.rules/`, and the
   relevant [`contracts/`](contracts/README.md) file move with the code, never
   in a follow-up. See [`40-agents.md`](40-agents.md).

## Self-check before you open or re-request review

```bash
cargo run -p xtask -- rules-check
cargo run -p xtask -- version verify-bump --base origin/main
cargo run -p xtask -- pr-check --body-file /tmp/pr-body.md
```

## Commit subjects

`commit-msg` (via `./scripts/install-githooks.sh`) enforces Conventional
Commits, and [`50-versioning.md`](50-versioning.md) derives the version bump
from them:

```text
type(scope): summary
```

- `type` ∈ `feat`, `fix`, `refactor`, `perf`, `test`, `docs`, `chore`,
  `build`, `ci`, `style`, `revert`.
- Subject starts **lowercase**, entire subject ≤ **72** characters.
- `!` before the colon (or a `BREAKING CHANGE:` footer) marks a breaking
  change.
- One commit per logical change. Do not batch unrelated work.

Examples: `feat(xtask): add version verify-bump gate`,
`docs(rules): pin local pre-prod commands`.

## Scope discipline

- Do not mix a rename, a refactor, and a behaviour change in one PR.
- Do not touch incentive, scoring, or consensus semantics unless that **is**
  the PR, in which case say so in the title and body and update the frozen
  contract deliberately.
- Never commit `deploy/env/*.env`, `deploy/secrets/**`, Terraform state,
  wallets, age identities, or `*.pem` / `*.key` / `*.age`.
- Branch protection, required checks, and `production` environment reviewers
  are **org settings**. A PR can add a check; it cannot make it required. Say
  so in the body instead of implying it is enforced.
